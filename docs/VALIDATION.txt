Correction validated 2026-11-01:
- The original v0.1.0 used an ANSI SetWindowsHookEx import with a Unicode
  CREATESTRUCT callback. Original tests checked final focus but failed to
  verify actual creation interception and invisibility. Those claims were
  insufficient; v0.1.0 has a known background-opening defect.
- Corrected import explicitly uses SetWindowsHookExW.
- Creation is identified by a native marker. A second thread-scoped hook
  applies DWM cloaking immediately after WM_NCCREATE, before showing Extra.
- Verified native marker=1, pre-show cloak marker=130 (WM_NCCREATE + 1),
  and DWMWA_CLOAKED app bit=1. WS_VISIBLE can be true while DWM cloaking
  keeps the window invisible; offscreen coordinates are not relied on.
- Actual worker stopped the running listed service, then passed a full
  controlled GHelper start/stop cycle. Each test ended with no active
  listed services, services_disabled=1, zero GHelper foreground activation
  events, temporary Extra closed, and both hooks removed.
- Repeated creation passed while the native DLL remained mapped.
- Foreground regression tests cover same-app windows, unrelated app
  switching, target activation, transient target activation, and the
  target already being foreground. No services are changed by that test.

Current hook binary: runtime/ExtraNoActivate-v5.dll (generated, ignored).
